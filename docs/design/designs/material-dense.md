# Material Dense — チップと一覧で「ひと目で多く」見せる社内ストア

**この内容は Claude の学習データ（記憶）に基づく。実物のページは今回読んでいない。数値は記憶によるもので、実物と異なる可能性がある。** 確信度は項目ごとに［高］［中］［低］で示す。公式ガイドライン（Material 3・Fluent 2・Steamworks の規格）の数値を**事実**、ストアの画面の記憶と、それをこのストアに当てはめたものを**推測**として分ける。3 章以降は、断りがなければ M3 の公開値［高］を土台にした当てはめ［中］である。項目名は `catalog.json`・`categories.json` の名前をそのまま使う。

## 1. 狙いと、参考にするストア

**狙い（一行）:** 毎日開く「ツールのストア」として、Play の骨格（チップ・横並びの一覧・1 色のアクセント・ストアがかけるアイコンの角丸）に Steam の密度（行の一覧・右のプレビュー・左の絞り込み・理由の一行）を加え、1280×800 の最初の 1 画面に特集 1 本＋一覧 6 行＋プレビュー 1 件を収める。

| ストア | 取り入れるもの | 理由 |
|---|---|---|
| Google Play / M3［高］ | チップを、所属の表示と絞り込みの両方に同じ形で使う。アイコンの角丸 20% をストアがかける。ボタンは 1 画面に 1 つで、文言は動詞か価格。影なし・白地・アクセント 1 色 | 使い方を 1 回覚えれば済み、作成者が用意する画像の質がばらついても一覧がそろって見える |
| Steam［高］ | 一覧は行で、注目のものだけカードにする。タブ付きの一覧＋右のホバープレビュー。理由の一行。Early Access の「入手の直前に文で区分を示す」やり方 | クリックせずに 8 件を比べられる。未審査のものを色で格下げしない |
| 取り入れない | Steam の 12px の本文・角丸 0〜2・ダーク固定・割引のラベル。Play の星・自動で切り替わる表示・「無料と書かない」こと | 要件（星を使わない・有償がある）と「しょぼくない」に反する |

## 2. 試作 v1 の欠点（当時の `store.html`）

1. **絵が 1 枚もない。**`.card` は名前・サブタイトル・チップ・メタ情報 2 行だけである。アイコンも見本もなく、ストアではなく課題管理の一覧に見える。「しょぼい」と言われた最大の原因である。
2. **色を 4 系統に分けている**（`--official` 青／`--indie` 橙／`--paid` 緑／`--warn` 赤）。ストアに共通する「無彩色＋1 色」の原則に反し、橙のインディーズは格下に見える。主ボタン `.btn.tier` の色が区分ごとに変わり、「押す色」が定まらない。`.nav .badge` の赤い件数も同じ問題がある（赤は「壊れうる」ことを示す色）。
3. **生成 AI の既定のデザインがそのまま残っている。**温かみのある生成り色 `#F5F4EF`＋スレート色の文字、左に 4px の色線を引いた `.tierbar` の囲み、`.stats` の KPI タイル、あちこちに散らばる 11px 太字の `.chip`、ホバーで浮く影。
4. **文字サイズの段差が小さく、検索がただの入力欄になっている。**本文 14〜詳細 22 の範囲に段が詰まり、カテゴリーの見出し 16 は段落に見える（ストアでは 20〜22）。`.search input` は 8px のパディングの入力欄で、長い placeholder が切れる（ストアでは 48〜56 のピルを中央に置く）。
5. **特集がない。**`features` の 4 件を使っておらず、ストアの印象を決める見せ場が無い。区分の切り替えがヘッダーの全体スイッチなので、区分をまたぐホームや一覧が作れない。
6. **カードがすべて同じ重さである。**`.row` に 230〜300px のカード 4 枚 × カテゴリー 8 つ＝32 枚の、同じ形の長方形が並ぶ。絞り込み・件数・並べ替えも無い。
7. **印が多すぎる。**1 枚に価格・区分・定番・審査状態のチップと、種類・カテゴリー・バージョン・日付が付く。ストアでは 1 つに絞っている。
8. **詳細が横から出るパネルである**（`.panel` 560px）。URL が無く、共有できない。`dl` の表だけで、見本・特徴・作成者への導線が無い。
9. **文言が説明過多になっている。**ストア名の副題、各設問の `.why`、フッターの長文。「オフィシャルにしたい」は状態ではなく願望を表している。

## 3. デザイントークン

**書体**［Fonts の存在は高、当てはめは中］: `--font: "Roboto", "Noto Sans JP", system-ui, "Segoe UI", "Yu Gothic UI", "Meiryo", sans-serif`。太さは 400 と 500 の 2 段。Noto の 500 が細く見えるなら、`--w-strong` の 1 か所を 700 に切り替える。

**文字サイズの段**（px/行送り・太さ）［M3 の型は高、当てはめは中］
| 役割 | 値 | 使う所 |
|---|---|---|
| display | 28/36・500 | 特集の題、詳細画面の名前 |
| headline | 22/28・500 | 一覧の見出し、画面の題 |
| title | 16/24・500 | 成果物カードの名前、節の見出し |
| body | 14/20・400（行の名前は 500） | 本文、行、チップ、入力 |
| body-s | 13/18・400・text-2 | サブタイトル、作成者、メタ情報 |
| label | 12/16・500 | アイブロウ（見出しの上の小さな文字。字間 .04em）、タブ、ラベル、件数 |
| micro | 11/16・500 | 「✓ 審査済み」、ピルの下の単位。**この 2 か所だけ** |

**色**（hex。トークンで持ち、部品に直書きしない）［M3・Fluent の値は高、組み合わせは中］
| トークン | ライト | ダーク |
|---|---|---|
| --bg | #FFFFFF | #1A1D21 |
| --surface-2（レール・ホバー・情報表） | #F3F4F6 | #23272C |
| --surface-3（押したとき・説明ボックス・行内のピルの面） | #E8EAED | #2D3238 |
| --line | rgba(0,0,0,.10) | rgba(255,255,255,.10) |
| --text / --text-2 / --text-3 | #1D1F22 / #5B6167 / #8A9096 | #E8EAED / #A9B0B7 / #7D848B |
| --accent（主ボタン・リンク・タブの下線・選択中のチップ） | #107C5A（白地で約 5.2:1） | #4FD1A0（文字 #0C1A14） |
| --accent-soft（選択中のチップの面） | #E3F3EC | #1E3B31 |
赤・橙・黄は使わない。カテゴリーの色相は数値 `--h` で持ち、面は `hsl(var(--h) 60% 46%)`、ダークモードでは彩度 50%・明度 40%。

**余白・グリッド**［M3 の値は高］: 4px 刻み（4/8/12/16/24/32/48）。左右の余白 16（<600）／24（<1024）／40（≥1024）。本文の最大幅 1200、2 列の画面は 792＋24＋384。行どうしの間は 0 で、1px の線で区切る（左 16 の inset）。格子の間隔 12、節どうしの間 32。

**角丸・影**: 8（カード・チップ・入力欄・情報表）／12（特集の大カード・プレビューのパネル）／完全な丸（主ボタン・検索窓・ピル）／アイコンは辺の 20%。影は通常時 0。浮く要素だけ `0 4px 16px rgba(0,0,0,.14)`。ダークモードでは影 0＋1px の線。

**高さ**: 行 56／64、成果物カード 96、カテゴリーのタイル 96、特集の大カード 300、主ボタン 40、行内のピル 28×72。

## 6. アイコンと特集の絵（外部画像なし）

**アイコン（データから毎回同じものを作る）**［推測］
- 色相はカテゴリーごとに固定する: 計算表 160／自動化 205／プロンプト・スキル 262／閲覧・可視化 20／デザイン仕様書 232／資料のひな形 40／図・アイコン 320／サンプルデータ 190。同じカテゴリーでそろいすぎないよう、`id` のハッシュで ±12° ずらす。
- ツール: `linear-gradient(135deg, hsl(h 62% 48%), hsl(h+28 58% 38%))` の面に白の記号（線 2px・丸端・辺の 58%）。素材: `hsl(h 55% 93%)` の紙色の面に `hsl(h 55% 38%)` の記号と、内側 1px の枠。**ツールは濃い面、素材は薄い面**。
- 記号はカテゴリーごとに 1 つ。24 グリッドの SVG を `<symbol>` で 8 個定義し、`<use>` で使う: 計算表＝格子／自動化＝循環の矢印／プロンプト・スキル＝吹き出し／閲覧・可視化＝3 本の棒／デザイン仕様書＝目盛り付きの枠／資料のひな形＝角の折れた紙／図・アイコン＝丸・四角・三角／サンプルデータ＝円柱。
- 角丸はストアが `border-radius: 20%` で一律にかける。作成者が 512 の正方形の画像を出せば、同じマスクをかけて差し替える。

**特集の絵**（大カードの右 40%）: `linear-gradient(120deg, hsl(hue 55% 30%), hsl(hue+30 60% 45%))`（`features[].hue`）。`items` 3 件のアイコン 96 を −6°／0°／6° に傾けて重ね、白 α.25 の 4px の縁を付ける（App Store のコレクションカードの型［中］）。文字は左に分けて置き、絵に重ねない。ダークモードでは明度を 8 下げる。

**見本のパネル**（詳細画面。スクリーンショットの代わり）: `files` の拡張子で 3 つの形に分ける——xlsx/docx/pptx/md など＝紙（白・角の折れ。拡張子を 20/500 の hue の文字で中央に）、html＝ブラウザ枠、zip＝フォルダ。背景は `hsl(h 55% 94%)`、下にファイル名 label。

**作成者のアバター**: 円 32、surface-3、頭文字。色は付けない（人の序列に見えないようにする）。

## 7. マイクロインタラクション［M3 の state layer は高、値は中］
- ホバー: 行とカードは、面を 120ms で surface-2 にする。持ち上げ・影・反転はしない。押したときは surface-3・100ms。
- タブ: 3px の下線が 200ms で滑る。プレビューのパネル: 行にホバーして 150ms 後に切り替え、120ms でクロスフェードする。行から離れても、最後の 1 件を表示したままにする。
- 詳細: ハッシュで遷移し、本文を 120ms でフェードインする。戻ったときは `history.state` のスクロール位置に復帰する。
- 入手: ピルが「入手」→ チェック 16＋「開く」に 200ms で変わり、スナックバー「『名前』を入手しました」を出す（左下・48px・4 秒・同時に 1 枚まで・text の色を反転した面。有償なら「申し込みを送りました」）。
- 絞り込み: 即時に反映する。条件のチップが左から並び、× で外せる。URL にも反映する。`/` で検索に移り、Esc で閉じる。
- sticky: ヘッダー 2 段（112）と詳細画面の右列（top 88）。`prefers-reduced-motion` では transition をすべて 0 にする。

## 8. この案の弱点と対策
1. **密度が「業務ツール」側に寄る。**本文 14・角丸 8・行 56 は 2 つのストアの中間だが、依頼者の言う「しょぼくない」は App Store 側にある［中］。対策: 特集の大カードとアイコン 64 に見た目の重さを集め、節どうしの間 32 を削らない。`--density` を 1 つのトークン（行 56/64、格子の間隔 12/16）で持つ。
2. **34 件だと、密な一覧でほぼ全件が見えてしまい、ストアが小さく見える。**対策: タブ付きの一覧は 8 行、成果物カードは 6 枚までにし、空のカテゴリーは隠す。
3. **タッチ操作ではホバープレビューが使えない。**対策: 1024 未満ではタップで詳細を開く。行だけで判断できる情報を行に置く。
4. **チップの帯・レール・タブという 3 つの絞り込み方が並ぶ。**対策: 絞り込みの入り口は上のチップだけにし、レールには同じ条件を表示する（チェックが連動する）。状態は 1 つの URL にまとめる。
5. **生成したアイコンは、同じカテゴリーの中で似てしまう。**対策: 色相の ±12° のずれと、ツール／素材の明暗の違いでばらつかせる。作成者が正方形の画像を出せる導線も残す。
6. **役割の判定と Google Fonts。**1 枚の HTML では審査担当者が誰か分からないので、`?role=reviewer` か localStorage で暫定的に判定する。本番では SSO の属性を使う。Google Fonts が CSP で止められる置き場所（SharePoint）［中］でも、代わりの書体で文字サイズの段は同じ数値になる。
7. **ダークモードで色相の面が濁る。**対策: 彩度と明度をトークンで 1 段落とし、白文字のコントラスト 4.5:1 を保つ。
