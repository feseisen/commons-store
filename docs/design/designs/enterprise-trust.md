# 案「企業向けのストア」— Slack App Directory・Atlassian Marketplace・Microsoft Store を参考にした社内ストア

**この内容は Claude の学習済みの知識に基づく。実物のページは今回読んでいない。数値は記憶によるもので、実物と異なる可能性がある**。確信度は項目ごとに［高］［中］［低］で示す。［高］は Fluent 2／WinUI の公開トークンや広く知られた仕様（事実）、［中］［低］はストアの画面の記憶と、それをこのストアに当てはめたもの（推測）である。3 章以降は、断りがなければ Fluent の公開値［高］を土台にした当てはめ［中］である。項目名は `catalog.json`・`categories.json` の名前をそのまま使う。

## 1. 狙いと、参考にするストア

**狙い（一行）:** 「誰が作り、誰が確かめたか」を主役に据える。Fluent の落ち着いた面（Mica 相当の灰＋白の Layer＋1px の枠）の上で、審査済み／未審査の境目と、カテゴリーによる分類だけでストアを成り立たせる。審査担当者には表と状態の文言を、一般の利用者にはボタン 1 つを、同じ画面構成の中で出す。

| ストア | 取り入れるもの | 理由 |
|---|---|---|
| Microsoft Store［高〜中］ | 左レールの区分（Apps／Gaming の位置にオフィシャル／インディーズ）、上部中央の検索、Mica＋Layer＋1px の枠、1 つのボタンの文言で状態を示す（Get→Install→Open）、Additional information の表、製品 ID を URL に持たせる | 会社の PC は Windows である。同じ面と余白の刻みなら、社内のほかのツールと並べても違和感が無い |
| Slack App Directory［中〜高］ | カードは**アイコン＋名前＋作成者＋短い説明**だけ。特集は静的な 4 列の格子。Permissions を平文で列挙する。ストアの外にあるものを「承認待ち」として別に扱う | 星を使わないストアの実例である。「掲載＝審査済み／ストアの外＝未審査」という関係が、このストアの区分そのものにあたる |
| Atlassian Marketplace［高〜中］ | バッジは「何を確かめたか」ごとに書く、Free／Paid の文字、右列に価格と主ボタン、Privacy & Security の欄 | 管理者が読む欄の型である。バッジの重ね掛け・3px の角丸・12px の本文は取り入れない |

取り入れないもの: 星・レビュー・インストール数、Partner Gold／Platinum（作成者の格付け）、Cloud Fortified の盾（記号）、Salesforce Labs の第 3 の枠、自動で切り替わるヒーロー。

## 2. 試作 v1 の欠点（当時の `store.html`）

1. **絵が 1 枚も無い。**`.card` は、名前・サブタイトル・チップ・メタ情報 2 行の文字だけである。Slack でさえアイコン 48〜64 を置く。課題管理の一覧に見える最大の原因である。
2. **色が 4 系統と、その淡色がある**（`--official` 紺／`--indie` 橙／`--paid` 緑／`--warn` 赤）。押せない所に色が付き、インディーズは警告色の橙で格下に見え、有償の緑は「進め」と読める。審査担当者向けの件数バッジは赤地に白字である。
3. **区分のバナーが Bootstrap の alert の型である**（左 4px の色線＋淡色の面＋色付きの h1）。切り替えに使う色付きの丸 `.dot` は、意味を覚えさせる記号になっている。生成 AI の既定のデザインの典型である。
4. **1 枚のカードにラベルが最大 5 つあり**、さらに「種類 › カテゴリー」と「v2.3 · 2026-09-12」が付く。信頼を示す表示がほかのラベルに埋もれ、主役になっていない。
5. **文字サイズの段差が潰れている**。本文 14／カード名 15／カテゴリーの見出し 16／h1 20／詳細 22。差が 1〜2px しかなく、階層が見えない。
6. **密度が管理画面のものになっている**。カードの内側 12〜14、格子の間 12、カテゴリーどうしの間 22、角丸は一律 10。`min-height:150` の同じ重さのボックスが並ぶ。
7. **詳細が右のドロワーで開く**。アイコンが無く、主ボタンの色が区分ごとに変わり（橙にもなる）、横に金額のチップと「作った人に連絡する」が並ぶので、押せるものが 3 つある。情報は 13px の dl で示している。
8. **`features[]`・`tagline`・`features`・`hue` を使っていない**。特集が無く、ホームはバナー＋種類のチップ＋カテゴリーごとの一覧の繰り返しになっている。
9. **文言がシステムの独り言になっている。**「入口をまたいで出しています（札で区別）」「（試作: ダウンロードは行いません）」など。placeholder が 27 字ある。
10. **状態が URL に無い**。詳細画面のリンクを人に送れない。
11. **カテゴリーの中を「目印の数 → 更新日」の順で並べている**。暗黙の順位が付き、星を外した意味が無くなる。
12. **スマホでヘッダーが 3 段に折り返し**、検索窓 36px・ボタン 38px で、目標の 44 を下回る。

## 3. デザイントークン

**色（Fluent の α の階層を、ライト #F3F3F3・ダーク #202020 の基調色に重ねる）**［α 値は WinUI の公開値で高、hex 換算は中］

| トークン | ライト | ダーク | 使う所 |
|---|---|---|---|
| `--bg` | #F3F3F3（Mica の代用） | #202020 | 地 |
| `--layer` | rgba(255,255,255,.70) ≒ #FBFBFB | rgba(255,255,255,.054) ≒ #2B2B2B | カード・パネル・レール |
| `--layer-alt` | rgba(0,0,0,.037) 重ね ≒ #F0F0F0 | rgba(255,255,255,.06) 重ね ≒ #363636 | ホバー・選択・灰色のボックス |
| `--stroke` | rgba(0,0,0,.058) ≒ #E5E5E5 | rgba(255,255,255,.084) ≒ #323232 | 枠・区切り |
| `--text-1` | rgba(0,0,0,.896) ≒ #1A1A1A | #FFFFFF | 名前・本文 |
| `--text-2` | rgba(0,0,0,.606) ≒ #616161 | rgba(255,255,255,.786) ≒ #CDCDCD | 作成者・サブタイトル・ラベル |
| `--text-3` | rgba(0,0,0,.446) ≒ #8A8A8A | rgba(255,255,255,.545) ≒ #8F8F8F | アイブロウ（見出しの上の小さな文字）・補足 |
| `--accent-fill` | #005FB8（文字 #FFF） | #60CDFF（文字 #000） | 主ボタン、選択中の下線 |
| `--accent-text` | #003E92 | #99EBFF | リンク、「すべて見る」 |
| `--focus` | #000 2px＋外 #FFF 1px | #FFF 2px＋外 #000 1px | フォーカスリング |

赤・橙・黄・緑は持ち込まない。「未審査」「有償」「差し戻し」は、`--text-2` の文字か `--layer-alt` の面で表す。色を持つのは、カテゴリーの色相（6 章）を使うアイコンと特集の面だけである。

**書体**［Google Fonts の指定は高、Segoe への近さは中］: `Open Sans`（400／600）＋ `Noto Sans JP`（400／600）。`font-family: "Open Sans","Noto Sans JP","Segoe UI Variable Text","Segoe UI","Yu Gothic UI",system-ui,sans-serif`。Open Sans は、Google Fonts の中で Segoe UI に最も近いヒューマニスト系のサンセリフである。**Google Fonts が CSP で止められても Segoe UI＋Yu Gothic UI で表示され、これは Microsoft Store の書体そのものである**。太さは 400 と 600 だけを使い、数字は `tabular-nums`。

**文字サイズの段**［WinUI の段は高、当てはめは中］: title-l 40/52・600（幅 400px では 32/40。特集のタイトル・区分の名前）／title 28/36・600（詳細画面のタイトル・h1）／subtitle 20/28・600（一覧の見出し・節・情報バーの値）／body-l-strong 16/22・600（カードの名前）／body-l 16/24・400（本文・lead）／body 14/20・400（サブタイトル・表の値）／caption 12/16・400（作成者・ラベル・価格・バッジ。アイブロウだけ 600・字間 0.04em）。12px 未満は使わない。

**余白・グリッド**［4px 刻みは高、値は中］: 刻み 4／8／12／16／24／32／40。左レール 72。本文の最大幅 1,240（左右 40 込み、中身 1,160）。左右の余白 16（<600）／24（<1024）／40。格子は 4 列（≥1024）・2 列（600〜1023）・1 列＝行（<600）、列の間 16。一覧どうしの間 40、見出しと中身の間 12、詳細画面の節どうしの間 32、カードの内側 16。行 72（アイコン 48）、タイル 176（アイコン 64）。押せる要素は 44×44 以上。

**角丸**［高］: 面（カード・パネル・ダイアログ）8、部品（ボタン・入力欄・チップ・表）4、検索窓だけ両端を完全に丸める、アイコンは辺の 22%（48→11、64→14、96→21、128→28）。**影**［中］: 通常時とホバー時は 0。浮く要素（メニュー・ダイアログ・トースト）は 0 8px 16px rgba(0,0,0,.14)。ダークモードでは 0 にして、`--stroke` を 1 段明るくする。

## 4. 画面ごとの構成

**全体の構成**（Microsoft Store の型）［中］。左レール 72px、`--layer`、右に 1px の `--stroke`。項目は上から、ホーム／オフィシャル／インディーズ／検索／自分のもの。下端に審査待ち（管理者にだけ出る。未処理の件数を `--text-2` の数字で添える）。各項目は 20px の線のアイコン＋caption で、選択中は左に 3×16 の `--accent-fill` の縦棒を付ける。上部のバー 56px: 左に「成果物のストア」subtitle、中央に検索窓（幅 480・高さ 44・両端が丸い形・placeholder「探す」）、右に主ボタン「公開する」（Slack の Build の位置）。<1024 ではレールを下タブ 5 つ（高さ 64）にする。URL は `#/home` `#/official` `#/indie/tool/spreadsheet` `#/item/a-0001` `#/maker/佐藤` `#/search?q=` `#/publish` `#/review` `#/mine`。

**ホーム**（両方の区分を混ぜて出す画面。カードに「✓ 審査済み」が出る）。上から: ①特集 2 枚（12 列の格子で 8:4）: 左に `features[0]`（story、f-1）、右に `features[1]`（collection、f-2）。自動では切り替えない ②**区分のタイル 2 枚**（横並び、高さ 120）: 「オフィシャル」＋`tiers[0].sub`＋「N 件」／「インディーズ」＋`tiers[1].sub`＋「N 件」。同じ面・同じ形で、違いは文言だけ。この 2 枚が、ストアの中の境目を示す ③一覧「定番」（副題 `signals[0].why`）: 区分をまたいで standard を持つもの 4 枚、更新日の新しい順、右端に「すべて見る」④一覧「人気上昇中」: 同じ型 ⑤**カテゴリーの一覧**: 「ツール」「素材」の subtitle の下に、カテゴリーのタイルを 4 枚ずつ（高さ 72、カテゴリーの色相のアイコン 40＋`shelves[].name` body-l-strong＋「N 件」›）。押すと `#/official/tool/spreadsheet` に移る。

**区分のページ**（オフィシャル／インディーズ）。上から: ①区分の見出し（高さ 120、背景は地のまま）: アイブロウ「区分」→ 名前 title-l → `tiers[].sub` body-l `--text-2`。**両方とも同じ見出し・同じ色にする**。インディーズだけ 1 行加える「作成者が直接公開したものです。詳細画面の『ストアによる確認』で、何が確認済みかを見てから入手できます」②その区分の特集（`features[].tier` で分ける）③種類のタブ「すべて／ツール／素材」（Fluent の Pivot: 選択中は 3px の `--accent-fill` の下線）④カテゴリー 8 つ（`kinds[].shelves[]` の順）: 見出し「計算表」subtitle＋アイブロウ「ツール」、右端に「すべて見る」。中身は 4 列 1 行で、更新日の順。**目印の数では並べない**。0 件のカテゴリーは出さない。この中では「✓ 審査済み」を出さない（見出しが審査済みであることを保証している）。

**カテゴリーの一覧（すべて見る）**: パンくず caption「オフィシャル › ツール › 計算表」→ カテゴリー名 title →「N 件」＋並べ替え 1 つ（Dropdown。既定は「最近更新」、ほかに「名前順」「新着」）＋絞り込み「価格: すべて／無償／有償」「作成者の部門」（選ぶと × 付きのチップになる）→ 行の一覧（5 章 B）。24 件を超えたら「もっと見る」を出す。

**詳細** `#/item/a-0001`。≥1024 は左列 320（sticky、top 72）＋右の本文。<1024 は縦に積む。
- 左列: アイコン 128 → `name` title（2 行まで）→ `tagline` body-l `--text-2` → 「作成者 佐藤（経理企画）」（名前は `#/maker/` へのリンク）→ 価格 body-l-strong「無償」／「¥5,000」＋caption「1部門あたり月額」→ **主ボタン**（幅いっぱい・高さ 40・角丸 4・`--accent-fill`）「入手」／「¥5,000」／「開く」／「入手済み」→ caption「入手できない場合 →」→ インディーズのときだけ**灰色の説明ボックス**（`--layer-alt`、角丸 8、内側 16。Steam の Early Access の型）: 「インディーズ（審査前）」／「確認されていないこと: 会社の情報の扱い、他の部門での動作」／`description` の先頭 2 行／requested なら「審査を申請中（9/26）」／「作成者に聞く」。returned は出さない
- 右の本文: ①**情報バー**（上に値 subtitle・下にラベル caption・1px の縦線・セルの幅 120）: 区分「オフィシャル／審査済み 8/20」・作成者「佐藤／経理企画」・更新「9/12／バージョン 2.3」・入手の傾向「定番／多くの部門で入手」（`signals` が空なら出さない）②**ストアによる確認**（Slack の Permissions と PyPI の Verified details の型。`--layer` のボックス、各行 40h、左に 16px のチェックの線画）: 「審査担当者が確認済み（2026-08-20）— 社内標準の集計として採用」（`review`）／「作成者は社員名簿の 佐藤（経理企画）」／「ファイル 1 件 monthly-summary.xlsx をストアで保管」／「参考にした成果物: 月次集計の計算表 ✓ 審査済み」（`references[]`、系譜）。インディーズでは 1 行目を「審査担当者の確認: まだ（作成者が申請中 9/26）」か「なし」にし、**チェックの代わりに空の丸**を置く。ほかの行は同じ ③**作成者からの情報**: 「特徴」`features[]` を小タイル 3 枚 →「説明」`description` body-l →「対応環境」`environments[]` をチップで示す（32h、角丸 4）④**これを参考にした成果物**（逆参照、行 3 つまで）⑤**追加情報**（Microsoft Store の型。左にラベル `--text-2`・右に値、2 列の格子）: 区分／審査日／作成者／公開日／更新日／バージョン／ファイル／対応環境／カテゴリー／連絡先 ⑥「同じ作成者の成果物」（行 3 つ）。

**検索**。入力が空のときは「最近更新」「定番」の一覧を出す。結果は「『集計』N 件」title → チップ「区分: すべて／オフィシャル／インディーズ」「無償／有償」「ツール／素材」→ 行（区分をまたぐので「✓ 審査済み」が出る）。0 件のときは「『x』に一致するものはありません」＋「言葉を短くする」「作成者の名前で探す」＋下に「最近更新」の一覧。

**公開のフォーム**。左 640 に設問のカード 7 枚（Card、角丸 8、内側 24）＋右 320 に**ライブプレビュー**（sticky。入力に合わせて 5 章 A のタイルがその場で描かれ、下に「こう並びます: インディーズ › ツール › 計算表」）。①名前（45 字）とサブタイトル（60 字、残りの字数を表示）②種類とカテゴリー: カテゴリーのタイル 8 枚から 1 つ選ぶ（6 章のアイコン付き。絵で選べる）③ファイル: 点線の枠「ここに置く」④無償／有償: 有償なら金額と単位の Dropdown「1人あたり月額／1部門あたり月額／1人分の買い切り」⑤対応環境: 既存の `environments` からチップで選ぶ ⑥参考にした成果物: 名前で検索して追加する ⑦**オフィシャルの審査**: スイッチ「審査を申請」＋「申請しなくても、インディーズにはすぐに公開されます。承認されるとオフィシャルに移ります」。末尾: 主ボタン「インディーズに公開する」（ON なら「公開して審査を申請する」）＋「公開する人: あなた（あなたの組織）」。送信すると `#/item/新ID` に移り、上に 1 行のバナー「公開し、審査を申請しました」を出す。

**審査待ち**（管理者だけ）: title →「承認待ち N 件」→ **表**（DataGrid の型、行 56h、列: 成果物（アイコン 32＋名前＋作成者）／申請日／カテゴリー／価格／操作「中身を見る」「承認する」「差し戻す」）。「中身を見る」で詳細を開くと、最上段に**審査画面の操作バー**（sticky、72h）: 「審査担当者として操作中」＋コメントの欄＋「承認する」（主）＋「差し戻す」（副。コメントが空なら押せず、「差し戻す理由を 1 行」と示す）。下に「審査の履歴」の表。**赤も緑も使わない**。差し戻されたものは、作成者の画面にだけ出る。

**自分が公開したもの**: title →「あなた（あなたの組織）」→ バナー「ここの数字はあなたにだけ見えます」→ 表（行 64h、列: 成果物／状態／数字／操作）。状態は文言だけで示す: 「インディーズに掲載中」「審査を申請中（9/26）」「差し戻し — 固有名詞の扱いを書いてから、再申請してください」「オフィシャル（8/20 承認）」。数字は「入手した部門 3」「参考にされた件数 2」（人名は出さない）。操作は「審査を申請する」「再申請する」「更新する」。

**空の状態**（1〜2 行＋ボタン 1 つ。絵も演出も使わない）: カテゴリー「このカテゴリーはまだ空です」＋「公開する」／自分のもの「まだ何も公開していません。答えるだけで公開できます」＋「公開する」／審査待ち「いま申請されているものはありません」／インディーズに何も無いとき「まだ誰も公開していません。最初の 1 つを公開する」。

## 5. カード 1 枚の構成

**A. タイル**（ホーム・区分・カテゴリーの格子。Slack／Atlassian の型）: 278×176、`--layer`、枠 1px、角丸 8、内側 16。上段は `grid-template-columns: 64px 1fr`、列間 12: 左にアイコン 64（角丸 14）、右に `name` body-l-strong（2 行を超える分は省略。**区分をまたぐ画面では、その直後に「✓ 審査済み」caption/600 `--text-2`**。チェックは 12px の線画）→ `maker.name`（`maker.org`）caption。中段は `summary` body `--text-2` 2 行。下段は caption: 左に価格「無償」／「¥5,000 · 1部門あたり月額」、右に理由の一語「定番」／「人気上昇中」（両方あれば「定番」）。**ボタンもラベルも無い**。面全体が押せる。バッジは 1 つまで。

**B. 行**（カテゴリーの一覧・検索・作成者・自分のもの・関連。Microsoft Store の順位付きの行から順位を除いた型）: 72h、`grid-template-columns: 48px 1fr auto`、列間 16、区切りは左 16 inset の 1px。左にアイコン 48。中央に 2 行: `name` body-l-strong＋「✓ 審査済み」／`tagline` · `maker.name`（`maker.org`）· 理由の一語、body `--text-2`。右: ボタン 32h×最小 96、角丸 4、`--layer`＋枠、文字は `--accent-text` 600 で「入手」「¥5,000」「開く」「入手済み」（有償なら、下に単位を caption で出す）。

**C. 特集の大カード**（story）: 8/12 列×280h、角丸 8、`hue` の面。左 60% にアイブロウ「特集 · オフィシャル」→ `title` title-l → `lead` body-l `--text-2` → 「3 件を見る ›」。右 40% に `items[]` のアイコンを 3 つ（96、−8／0／+8px ずつ上下にずらす）。文字を絵に重ねない。押すと `#/feature/f-1` を開く（同じ面 200h＋`body`＋行 3 つ）。

**D. コレクション**（4/12 列×280h）: `--layer`、左端に 4px の `hue` の縦線。アイブロウ「コレクション · インディーズ」→ `title` subtitle → `lead` caption → 行を 3 つ（56h、アイコン 32、名前だけ）。`body` が空でも崩れないこと（f-4）。

**E. 「特徴」の小タイル**: `--layer-alt`、角丸 4、内側 12、チェックの線画 16＋body。区分のタイルとカテゴリーのタイルは 4 章を参照。

## 6. アイコンと特集の絵の生成（外部の画像は使わない）

**アイコン**: 8 つのカテゴリーに色相を固定し、そのカテゴリーの色相のタイルに、カテゴリーの記号を白の線画で置く。`hue`: 計算表 150／自動化 210／プロンプト 265／閲覧・可視化 30／デザイン仕様書 232／資料のひな形 190／図・アイコン 330／サンプルデータ 45。タイルは `linear-gradient(135deg, hsl(h 45% 46%), hsl(h 50% 34%))`、角丸は辺の 22%、ライト・ダーク共通（ストアが一律にかけるマスク。Play の型［高］）。記号は 24×24 の viewBox、線 1.75px、白: 計算表＝3×3 の格子、自動化＝循環する矢印、プロンプト＝吹き出しに「>」、閲覧＝棒 3 本、仕様書＝枠に上の帯と左の列、ひな形＝紙に横線 3 本、図・アイコン＝丸・四角・三角、データ＝円筒。同じカテゴリーの成果物が同じ絵にならないよう、`id` の末尾 2 桁で明度を ±6% 変え、記号の置き方を 4 通り（中央／右下寄せ／2 つ／反転）にする［低。効果は試作で見る］。作成者が画像を持ち込んだら、同じマスクをかけて差し替える。

**特集の面**: `features[].hue` から作る。ライトは `linear-gradient(120deg, hsl(h 40% 94%), hsl(h 45% 88%))`、ダークは `hsl(h 25% 22%) → hsl(h 25% 16%)`。面が淡いので文字は `--text-1` のままでよく、scrim は要らない。右にアイコンを 3 つ並べるだけで、「集めた」ことが絵で伝わる（Slack の特集バナーの型［中］）。**作成者**の絵は作らない。名前＋部門の文字だけにする（Slack・Atlassian の型［高］）。

## 7. マイクロインタラクション

Fluent の動きの値: fast 100ms／normal 200ms／slow 300ms、イージング曲線は `cubic-bezier(.33,0,.67,1)`、表示されるときは `cubic-bezier(.1,.9,.2,1)`［中］。`prefers-reduced-motion` ではすべて 0。

- **ホバー**: タイルと行は `--layer-alt` の面にし、枠を 1 段濃くする（100ms）。持ち上げも影も付けない。ボタンは面を 90% にし、押したときは 80%＋文字 70%（Fluent の pressed［高］）。フォーカスは `--focus` の二重のリング。
- **入手**: 「入手」→「入手中…」（16px の進捗リング、600ms）→「開く」（ツール）／「入手済み」（素材）。有償なら先にダイアログ（480w、影あり）を出す: 「利用の申し込み — ¥5,000 / 1部門あたり月額。費用は部門に配賦されます」＋「申し込む」「やめる」。
- **詳細**: ページとして遷移する（ドロワーにしない）。本文を opacity 0→1・translateY 8→0 で 200ms かけて表示し、スクロール位置は先頭に戻す。戻る操作は、ブラウザの戻る／パンくず／レールで行う。
- **トースト**: 右下、360w、`--layer`＋枠＋影、4 秒表示。チェックの線画＋「『月次集計の計算表』を入手しました」。ダークモードでは影 0＋枠。
- **スクロール**: レールと上部のバーは固定し、詳細画面の左列は sticky にする。一覧は横スクロールしない。「もっと見る」は 24 件ずつ追加し、追加した先頭の項目にフォーカスを移す。
- **切り替え**: Pivot の下線は 200ms で横に滑る。チップの追加・削除は 100ms のフェード。公開のフォームのプレビューは、入力のたびにすぐ描き直す。

## 8. この案の弱点と対策

1. **角丸 8／4 と灰色の面は「業務ツール」寄りで、App Store の華やかさが無い**。対策: 絵の量で補う——タイルのアイコン 64、詳細画面 128、特集にアイコン 96×3。文字サイズの段は WinUI の 40／28／20 をそのまま使い、一覧どうしの間を 40 にして余白を惜しまない。
2. **静的な 4 列では 1 つのカテゴリーに 4 件しか見せられず、34 件では 1〜2 件しかないカテゴリーができる**。対策: 0 件のカテゴリーは隠し、1〜2 件のものも同じ格子で出す。数字を出さないので、寂しく見える分は「作成者」と「更新日」で補う。
3. **「ストアによる確認」の文面で、インディーズが劣って見えるおそれがある**。対策: ストアの定型文だけを使い、「未検証」「注意」という語を使わない。空の丸は「まだ」の意味で使い、色を付けない。
4. **「✓ 審査済み」が出るのはホーム・検索・作成者・自分のものの画面だけ**という規則を、一般の利用者が覚えられるか。対策: 区分のページの見出しで「すべて審査済み」と言い切り、バッジが出る画面には必ず上に区分のチップを置く。バッジの有無と区分が一対一で対応する。
5. **Mica と Google Fonts は環境に左右される**。対策: 地は #F3F3F3 の平面にし、Layer の α だけを取り入れる。フォントは、読み込めないときの代わりが Segoe UI＋Yu Gothic UI なので崩れない。
6. **審査待ちの表は、スマホでは横に長すぎる**。対策: <600 では行カード（成果物→状態→操作を縦に積む）に変える。
7. **SharePoint に埋め込むと、ハッシュによる画面の切り替えが効かないことがある**［低］。対策: 効かないときは `sessionStorage` に状態を保存し、「この成果物のリンク」ボタンで完全な URL を出す。
