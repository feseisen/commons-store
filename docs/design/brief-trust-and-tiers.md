# 信頼の印と区分 — 社内の成果物ストアへの指針

**この内容は Claude の学習データ（記憶）に基づく。実物のページは今回読んでいない。数値は記憶であり、実物と違いうる。**
材料は `research/` の 14 件である（同じく記憶に基づく）。確信の度合い［高］［中］［低］は調査から引き継ぎ、**事実**＝公式に告知された制度名・公開仕様、**推測**＝画面についての記憶と、このストアへの当てはめ、に分ける。第 2 章以降はすべて推測である。扱うのは「信頼の印と区分」だけ——審査済み／未審査、無償／有償、作成者の見せ方、星を使わずに良さを伝える方法。骨格と動線は `brief-ia-flows.md`、寸法と色は `brief-visual.md` に譲る。

**このストアの前提**（`categories.json`・`catalog.json`）: 区分は 2 つ（オフィシャル＝審査済み、インディーズ＝審査なし・玉石混交でよい）。審査の状態は none／requested／returned／approved。星の代わりの手がかりは「定番」「人気上昇中」。価格は無償か有償（有償は金額＋単位。単位は「1部門あたり月額」など）。作成者は名前＋部門で示す。成果物には、バージョン・更新日・対応環境・「参考にした成果物」（references）が付く。

## 1. 世界のストアに共通する法則（実例をストア名つきで）

**T1. 「掲載されている＝審査済み」のストアには、審査済みのバッジが無い。印は、少数の特別なものにだけ付く。**［高］App Store の Editors' Choice、Play のエディターのおすすめ、Slack・Atlassian・AppExchange（掲載前の審査が前提）、Setapp（「チームが全アプリを審査する」の一文でストア全体が印になる）、Notion（Notion Picks は横並びの一覧の名前）。**印が無い＝普通**なので、印の付かない大多数が劣って見えない。

**T2. 未審査のものも掲載するストアは、境目を「区分」か「入手の直前の文章」で引き、一覧のカードでは引かない。**Steam の Early Access は、購入欄の直前に囲みの帯・注意文・開発者の Q&A を置き、一覧ではタグだけ［高］（帯の色は記憶が一致しない。黄色の地だったとする記憶もある［中］）。Product Hunt は同じ画面で Featured／All の二層に分ける［中〜高］。Slack はカスタムアプリを「承認待ち」として別に扱う（ストアに無い＝未審査）［高］。反面教師は、AMO の淡黄色の注意箱「not actively monitored for security by Mozilla」（警告の調子が強く、公開する側を萎縮させる）［高］と、Microsoft Store の「provided and updated by <発行元>」（詳細の一文だけで区別するので、一目では分からない）［中］。

**T3. 印は「成果物」と「作成者」の 2 つの軸に分かれ、混ぜない。**Chrome ウェブストアの Featured（成果物の品質）と Established publisher（作成者の本人確認）［高］。VS Code の Verified publisher は、**拡張機能ではなく、発行者がドメインを所有していること**の印［高］。ThemeForest の Quality checked by Envato（物）と Elite Author（人。累計売上 $75k 超）［高］。

**T4. 印は「何を確かめたか」を示す。「良い」とは言わない。**PyPI は詳細を Verified details（ストアが確かめたもの。緑のチェック）と Unverified details（作成者が記載したもの）の二つに分ける［中〜高］。npm の Provenance は、「GitHub Actions でビルド・署名された」という由来の事実を示す［中］。Steam Deck Verified は、**技術的に適合しているという印であって、品質の印ではない**［高］。Atlassian は「動作保証」「セキュリティ」「作成者がサポート」を別々の印にしており、どれも無くても掲載される［高］。

**T5. 公式であることは作成者の名前で示す。バッジより控えめで、個人のものと同じ一覧に並べられる。**Canva「by Canva Creative Studio」、Figma「Figma」、Unity「Unity Technologies」、HF の名前空間 `google/`［いずれも高］。作成者の名前は常に表示する: AMO の「by 作者名」（題名の直下。作者のページへ移る）、Play の開発者名（名前の直下。リンク）［高］、Gumroad の丸いアバター＋名前（カードに常に表示）［中〜高］。Slack だけはカードに作成者を出さず、詳細でしか分からない［中］。

**T6. 否定の印（無い・違う）は灰色の 1 行で示し、警告色を使わない。**Mac App Store の「Not verified for macOS」［高］。VS Code は、Verified の無いものを「未検証」とは書かない［高］。一方で、**「壊れるおそれがある・消える」段階のものだけは色を持つ**: VS Code の Preview（黄）／Pre-Release（緑）／Deprecated（警告色）［中］、npm の非推奨を示す赤い帯［高］。色は「状態の危うさ」に、文字は「誰が確かめたか」に使い分けられている［合成、中］。

**T7. 星の無いストアは成り立っている。代わりに「理由の一行」「一覧の名前」「時刻」「仕様表」が信頼を支える。**星の無い例: Slack（作成者＋短い説明＋審査だけ）［中〜高］、Canva（カードに数字を一切出さない）［高］、HF・npm・PyPI（レビューの仕組みそのものが無い）［高］。代わりになる型: Steam は「理由の一行」（Now Available／Recently Updated／Recommended by your friends）を題名の下に置き、なぜここに出ているかを示す［高］。Gumroad（Staff picks／Hot and new）・Play（「〜をインストールしたあなたに」）は、**横並びの一覧の名前で扱いに差を付ける**［中〜高］。HF の「Updated 3 days ago」、Mac の Version History、Elements の Properties の表は、「いつ更新されたか・何が変わったか・どこで動くか」で信頼を組み立てる［高］。

**T8. 価格は「値札」か「ボタン」で示す。無料の書き方は「無料が既定かどうか」で決まる。**App Store は GET／価格をピルの文言にする［高］。Play は無料を書かない（無料が既定）［高］。Gumroad は無料でも「$0」を、同じ値札・同じ位置に出す［中〜高］。カードに金額を出さず言葉で示す型: JetBrains の「Free／Paid」、Atlassian の「Free／Paid via Atlassian」（詳細で Starts at）［中〜高］。反面教師: Microsoft Store の「Free+」、Canva の王冠（意味を覚えないと読めない記号）［中／高］。

**T9. 導入済みであることは、印ではなくボタンの文言か隅の帯で示す。**App Store の OPEN／雲のアイコン［高］、Microsoft Store の Get→Install→Open［高］、Steam の IN LIBRARY（カプセル画像の右上）［中］。

## 2. 社内の成果物ストアにそのまま持ち込む指針（具体的・数値つき）

すべて推測である（T1〜T9 の当てはめ）。寸法は `brief-visual.md` の段階（ラベル 11px/600・第二の文字色、情報表の角丸 10、内側の余白 16）を使う。

**P1. 境目は区分で引く。カードの形は両方の区分で完全に同じにする。**（T2）区分のページの先頭に、灰色の 1 行（13px、第二の文字色）を置く: オフィシャルは「審査済み。会社が『皆さん使ってよい』と認めたもの」、インディーズは「審査なし。作った人がすぐ出せる」。この 1 行だけで区分の意味を示し（Setapp の型）、一覧の形・ピル・色・アイコンの角丸は変えない。

**P2. 印に使う言葉は 3 語だけ——「審査済み」「定番」「人気上昇中」。**アイコンだけの印・色付きのリボン・盾の印は使わない。
- **「✓ 審査済み」**は成果物の印である。区分の中の一覧では出さない（区分のページの 1 行が保証している）。**区分をまたぐ画面**（検索結果、ホームの横並びの一覧、作成者のページ、マイライブラリ）でだけ、名前の直後に 11px/600・第二の文字色で出す。印が無ければインディーズだと一意に読める（Chrome ウェブストアの型）。
- 「定番」「人気上昇中」は印ではなく**理由を表す一語**で、カードのメタ情報の行に「by 佐藤（経理企画）· 定番」の形で出す（Steam の理由の一行）。カード 1 枚に付ける印は「✓ 審査済み」の 1 つまで。

**P3. 「審査済み」では、誰が・いつ・何を確かめたかを示す。**（T4）詳細の情報の帯に「区分」の欄を置く（値 20px「オフィシャル」／「インディーズ」、ラベル 11px「審査済み 8/20」／「審査前」）。情報表は 2 つのグループに分ける: **「ストアによる確認」**（区分／審査日と審査担当者／審査担当者のコメント（review.note）／公開日／更新日／バージョン／ファイル）と、**「作成者からの情報」**（対応環境／特徴／説明）。PyPI の型である。インディーズでも前者は空にならない（公開日・更新日・ファイル・作成者は、ストアが機械的に持っている事実なので）。

**P4. インディーズの詳細には、主ボタンの直前に灰色の説明ボックスを置く。**（T2、Steam の Early Access の型）面は情報表と同じ灰色、角丸 10、内側の余白 16。**黄・赤は使わない**。中身: 見出し「インディーズ（審査前）」13px/600 → 「作成者: 中村（営業支援）」→ 「確認されていないこと: 会社の情報の扱い、他の部門での動作」（ストアの定型文）→ 作成者による説明（description の先頭 2 行）→ リンク「作成者に問い合わせる」。requested の状態なら「審査を申請中（9/26）」の 1 行を足す。**returned（差し戻し）は利用者に見せない**——作成者と審査担当者の間の話であり、見せると格下げになる。

**P5. 作成者は「by 名前（部門）」の形でカードと詳細に常に表示し、押すと作成者のページへ移る。**（T5）作成者のページには、名前・部門・連絡先と、2 つの横並びの一覧「審査済みのもの」「インディーズのもの」を置く（件数は出さない）。**作成者の印は足さない**——社内は SSO で全員が本人確認済みなので、Verified publisher に相当するのは「名前が社員名簿と一致する」こと自体である。印を作ると、印の無い人が未検証に見える（T3・T6）。公式のもの（情シスなどが作ったもの）も部門名で分かるので、専用のバッジは作らない。成果物の審査（区分）と人という 2 つの軸は混ぜない。

**P6. 「定番」「人気上昇中」は数字も順位も出さず、一覧の名前と、理由を表す一語で示す。**（T7）
- 一覧「定番」の副題は「長く、多くの部門で入手されている」、一覧「人気上昇中」の副題は「この 30 日で入手が増えた」。**一覧の中は更新日の新しい順に並べる。入手数の順には並べない**（順位が暗に入り込むため）。順位の番号は付けない。
- 判定のしきい値（仮置き）［低］: 定番＝入手した部門が 3 つ以上、初回の公開から 90 日以上、直近 90 日に入手がある。人気上昇中＝直近 30 日の入手が、その前の 30 日の 2 倍以上かつ 5 件以上。両方に当てはまれば「定番」だけを付ける。**どちらかが区分内の成果物の 2 割を超えたら、しきい値が緩すぎる**（多くのものに付く印は意味を失う。T1）。
- 詳細では情報の帯の欄で示す（値「定番」、ラベル「多くの部門で入手」）。ツールチップだけに意味を任せない。
- 数を示したいときは「誰が」に言い換える: 情報表に「入手している部門: 経理企画、物流、総務」と出す（部門名までにし、人名は出さない。Steam の Recommended by your friends の型）［低］。件数・利用者数は、カードにも詳細にも出さない。

**P7. 「今も手入れされているか」は、更新日とバージョンで示す。**（T7）カードのメタ情報の行では相対的な時刻「3 日前に更新」（HF の型）、情報表では日付（年月日）・バージョン・「バージョン履歴」（Mac の型）で示す。古いものに「古い」という印は付けない——日付がそれを示している。

**P8. 無償／有償は、カードではピルの文言で、詳細では文字で示す。**（T8）無償＝ピル「入手」（金額が無い＝無償。App Store の GET の型）。有償＝ピルに金額「¥5,000」を出し、単位はピルの下に 9〜10px の灰色の文字で「1部門あたり月額」と添える（App Store の In-App Purchases の位置）。詳細の情報の帯に「価格」の欄を置く（値「無償」／「¥5,000」、ラベル「1部門あたり月額」）。**ピルの色・形は無償も有償も同じ**にする。押した後の流れが入手と違う（申し込みが挟まる）ときも文言は変えず、押した後の 1 画面で「利用の申し込み（費用は部門に配賦）」と示す。値引き・期限・王冠・「有償+」は持ち込まない。

**P9. 導入済みであることはピルの文言で示す。**「開く」（ツール）／「入手済み」（素材）。隅の帯や別の印は足さない（T9）。

**P10. 「参考にした成果物」は、信頼の系譜として詳細に出す。**references でオフィシャルのものを指しているインディーズの成果物（例: 棚卸しの差分チェック → 月次集計の計算表）は、情報表に「参考にした成果物: 月次集計の計算表（✓ 審査済み）」のリンクを出す（HF の Model tree の型）。審査前でも「審査済みの土台の上にある」ことが読み取れる。

**P11. 追加の印は「今週のおすすめ」の横並びの一覧 1 つだけ。**審査担当者が人手で選ぶ一覧は 1 つまで（Editors' Choice に当たるものを一覧の名前で示す）。カードにバッジは付けず、見出しの上に添える小さな見出し（アイブロウ）11px/600 で示す。更新が止まったら一覧ごと消す。

## 3. 持ち込んではいけないもの（理由）

- **星・レビュー・件数・順位・upvote・いいね・複製数**（Play・Steam・Atlassian・ThemeForest・Product Hunt・Figma・VS Code）。要件で置かないと決まっている。母数が小さいと「4.5 ★ (3)」「♥ 0」が並ぶ［高］。
- **未審査のものへの警告色・警告文**（AMO）。公開する人が減る。区分は文章で示し、色は「壊れるおそれがある」ものにだけ使う（T6）［高］。
- **審査の有無を詳細ページの一文だけで区別すること**（Microsoft Store）。区分で分ける［中］。
- **作成者を実績で格付けする印**（ThemeForest の Elite Author、Atlassian の Partner Gold/Platinum）。社内では部署間の序列に見え、「印が無い＝新人」と受け取られる［高］。
- **作成者の本人確認の印**（VS Code の Verified publisher、CWS の Established publisher）。SSO を使う社内では意味が無く、印の無い人が未検証に見える（P5）［中］。
- **印の重ね掛け**（Atlassian の 6 種類）。利用者に意味を覚えさせることになる。社内では「審査済み」の 1 語で足りる［中］。
- **意味を覚えないと読めない記号**（Canva の王冠、Microsoft Store の Free+、npm の p/q/m の棒、盾だけの印）。文字で書く［中〜高］。
- **「公式だが保証なし」という 3 つ目の枠**（Salesforce Labs）。区分が 3 つになり、2 つの区分に分けた意味が薄れる。同じことは「インディーズ＋作成者の部門名」で読み取れる［中］。
- **数で並べる「定番」**（Top Downloads、Best sellers）。順位が暗に入り込み、星を外した意味が無くなる［中］。
- **期間限定の無料配布・セール**（Fab の Limited-Time Free、Steam の割引ラベル）。社内に値引きは無く、暖色のラベルは「有償」の表示と紛らわしい［高］。
- **人によって中身が変わる一覧**（Steam の個人化）と、**コメント欄・Q&A・レビューのタブ**（Figma・VS Code・JetBrains）。信頼は「誰が見ても同じ一覧」の上に成り立ち、空の欄はストアを寂れて見せる［中］。

## 4. 迷ったときの判定

1. **その印は「何を確かめたか」を 1 行で言えるか。**言えないなら印ではなく、一覧の名前にする（T4・P3）。
2. **印の無いものを並べて見て、劣って見えないか。**劣って見えるなら、色か位置が間違っている。灰色の文字・同じ行・同じピルに戻す（T1・T6）。
3. **数を出したくなったら、母数が 3 のときの画面を描いてみる。**寂しく見えるなら、「誰が」（部門名）か「いつ」（更新日）に置き換える（P6・P7）。
4. **警告色を使いたくなったら、それが「壊れるおそれがある・消える」の話か、「誰が確かめたか」の話かを考える。**後者なら灰色にする（T6）。
5. **区分をまたぐ画面（検索・ホーム・作成者のページ・ライブラリ）で、区分が読み取れるか。**「✓ 審査済み」と印なしが、それぞれの区分に一意に対応しているか（P2）。
6. **作成者の名前が消える画面は無いか。その印は「成果物」の話か「人」の話か。**名前が抜けていたら戻し、混ざっていたら分ける。人の印は今は作らない（T3・T5・P5）。
7. **有償の成果物で、ボタンの文言から、押した後に何が起きるかが読み取れるか。**読み取れないなら押した後の画面で説明し、ボタンの文言は変えない（P8）。
8. **審査の基準が変わったら、印の文言も合わせて変えたか。**印は基準の名前である。ずれたら印が事実と合わなくなる（T4）。
9. **最後に「その情報は入手の判断に使われるか」を考える。**使われないなら情報表へ移す。カードに残すのは、名前・サブタイトル・作成者・理由を表す一語・ピルだけ。
