# 情報設計と動線 — 社内の成果物ストアへの指針

**この内容は Claude の学習済みの知識に基づく。実物のページは今回読んでいない。数値は記憶によるもので、実物と違いうる。**
材料は `research/` の 14 件である。確信の度合い［高］［中］［低］は調査から引き継いだ。**事実**＝公式ガイドラインの数値や広く知られた仕様、**推測**＝「こうだったはず」「社内ではこうすべき」という当てはめ。第 2 章はすべて推測である（各ストアの観察を、このストアの要件——2 つの区分・大カテゴリー→中カテゴリー・作成者の名前・無償／有償・星なし・専門家でない利用者がボタンを押すだけで済む——に当てはめたもの）。扱うのは情報設計と動線だけで、寸法と色の細部はほかの指針（brief）に譲る。

## 1. 世界のストアに共通する法則（実例つき）

**L1. 骨格は 1 つの型を全ページで使い回す**。Mac App Store は Discover も Create/Work も各カテゴリーも、「特集カード＋Top Free/Paid の横並びの一覧」という同じ型である［高］。使い方を覚えるのが 1 回で済む。

**L2. ナビは常に表示し、項目は 5 つ以内にする。ハンバーガーメニューは使わない**。App Store の下のタブは 5 つ［高］、Play は 2020 年ごろにハンバーガーメニューを廃止した［高］。NN/g によると、ハンバーガーメニューは機能を見つけにくくする［中］。

**L3. 検索語が空でも、横並びの一覧を出す**。VS Code のアプリ内では、検索語が無くても INSTALLED／POPULAR／RECOMMENDED が出る［高］。反面教師は npm（トップページに一覧が無い）［高］と VS Code Web（ヒーロー領域が検索窓だけで、「しょぼい」と感じさせる原因になっている）［中］。

**L4. 「何をしたいか」から探せる入り口を、ジャンルとは別の軸として用意する**。Mac App Store の Create／Work／Play／Develop［高］、Atlassian の「先に製品を選ばせる」形［高］。専門家でない人も、自分の仕事を手がかりにたどっていける。

**L5. カテゴリーは大→中の 2 段にする。1 段に 20 個並ぶと目で追いきれない**。新しい CWS は大 3 → 中 18［中〜高］。Unity はカテゴリーバーにホバーするとメガメニューが開き、詳細のパンくずがカテゴリーの階層へ戻る道になる［高］。1 段のままの VS Code（約 20）・Play（約 32）［高］、Fab（大 14）［中］は、タグやチップで足りない所を補っている。

**L6. 一覧は行の形、注目させたいものはカードの形にする。すべてをカードにはしない**。Steam の検索結果は約 45〜50px の行で、カードの 3〜4 倍の密度がある［高］。App Store の横並びの一覧は、「行型のカード 3 行＝1 ページ」を横にめくる形である［高］。NN/g によると、同じ種類の項目を比べるならリストのほうが速い［高］。

**L7. 詳細の最初の 1 画面に「何か・誰が作ったか・いくらか・入手ボタン」を収める**。App Store・Play・Steam はそうなっている［高］。Unity・Figma・Notion は右 1/3 のパネルに価格・主ボタン・情報欄を集め、スクロールせずに決められるようにしている［高／中］。

**L8. 主ボタンは 1 画面に 1 つにし、ボタンの文言がそのまま状態を表すようにする**。App Store は GET／価格／OPEN［高］、MS Store は Get → Install → Open → Update（「ダウンロード」と「インストール」を分けない）［高］。Gumroad は「I want this!」の 1 種類だけで、購入と無料での受け取りを区別しない［高］。Web では、うまくいかないときの逃げ道を横に置く（VS Code の Trouble Installing? → 1 回でコピー）［高］。

**L9. 絞り込みは「選択中の条件がチップで見え、× で外せ、URL に残る」形にし、件数と並べ替え 1 つを添える**。HF（左にフィルター、先頭に総数と Sort）［高］、Unity（適用中の条件のチップ＋Clear all）［中］。Play は、所属の表示と絞り込みの両方に同じ形のチップを使う［高］。NN/g によると、無限スクロールより「もっと見る」ボタンのほうが良い［中］。

**L10. 審査済み／未審査の境目は「ストアの入り口（区分）」で引く。個々のバッジでは引かない**。Slack はカスタムアプリを「承認待ち」として別に扱う（ストアに無い＝未審査）［高］。Product Hunt は同じ画面で Featured／All の二層に分ける［中〜高］。Setapp は「チームが全アプリを審査する」の一文で、ストアに載っていること自体が審査済みの証しになっており、個々のアプリにバッジを付けない［中〜高］。

**L11. 未審査のものを警告色で格下げせず、「入手の直前」に文章で説明する**。Steam の Early Access は、購入欄の直前に枠で囲んだバナー・注意文・開発者の Q&A を置き、一覧にはラベルを付けない［高］。AMO の淡黄色の注意ボックスは警告の調子が強く、公開する側を萎縮させる［高］。

**L12. 作成者の名前はカードと詳細に常に表示し、押すとその人のすべての成果物へ移れるようにする。**「by ○○」（Canva・AMO・Unity）［高］、名前空間 `org/name`（HF・npm。名前空間そのものが、公式か個人かの手がかりになる）［高］。

**L13. 空の状態では「なぜ空か」と「次にできること」を 1〜2 行で示す。イラストも演出も置かない**。Mac の「No Updates Available／Your apps are up to date」［高］、Unity の「No results for …」＋フィルターを減らす提案［中］。

**L14. 公開の流れは「提出する → 待つ → 掲載される」の 3 段階で、状態は文言で作成者に示す**。この点は材料が少ない。JetBrains は公開前に人が審査する（通常 2 営業日）［中］。Steam Direct は誰でも掲載される［高］。Slack は「承認待ち」という文言で示す［高］。

## 2. 社内ストアにそのまま持ち込む指針（画面ごと・上から順）

L1〜L14 をこのストアの要件に当てはめた**推測**である。数値は、M3／HIG／Fluent の公開値［高］と各ストアの観察［中］から取った出発点である。

**G1. 全体のナビ（常に見える 5 つ）**。左のレール（幅 60〜70px、MS Store の型［中］）か、上のタブにする。項目は「ホーム／オフィシャル／インディーズ／検索／マイライブラリ」。**オフィシャルとインディーズは、MS Store の Apps／Gaming と同じ最上位の位置づけ**で、カテゴリーより上にある。検索窓は上部の中央に 1 つ置く（高さ 56px のピル、M3［高］）。

**G2. ホーム（上から順に）**。①固定の特集 1 枚（自動では切り替えない。画像が無ければアイコン＋色の面）②「今週のおすすめ」＝人が選ぶ横並びの一覧 ③「新着」「最近更新」＝数値から自動で決まる一覧 ④大カテゴリーのタイル 6〜8 個（色付きのアイコン、HF の型［中］）。横並びの一覧は App Store の型で、「3 行×横にめくる」形にする（行：アイコン 64px・名前・サブタイトル・右端のピル、行の高さ 80px［高〜中］）。一覧の見出しには、そこに並ぶ理由を文で書く（「先月更新された」。Play の型［中］）。

**G3. 区分のページ（オフィシャル／インディーズ）**。ホームと同じ型にする。先頭に灰色の文を 1 行だけ足す：「ここにあるものはすべて審査済み」／「作成者が直接公開したもの。審査前」。**オフィシャルとインディーズの違いはこの 1 行だけにし、色も一覧の形もピルも変えない。**

**G4. カテゴリー → 一覧**。大カテゴリー 6〜8 → 中カテゴリー 3〜8。入り口は、カテゴリーバーのメガメニュー（Unity の型［高］）と、画面の左に置く件数付きのフィルターの階層（幅 240〜260px［中］）。一覧の上に「N 件」と並べ替え 1 つを置く（既定は「最近更新」、ほかに「名前順」「新着」）。フィルターは「区分／無償・有償／中カテゴリー／作成者」の 4 つの軸で足りる。選択中の条件は × 付きのチップで示し、状態は URL に載せる（チャットに貼れるように）。続きは「もっと見る」で読み込む。

**G5. 検索**。検索窓は常に 1 つ表示し、入力中に候補を出す。**検索語が空でも「最近更新」「よく使われる」の一覧を出す**。結果は行の形で、上に G4 と同じチップを置く。0 件のときは「『x』に一致するものはありません」＋「フィルターを外す」「別の言葉で探す」を示し、その下に新着の一覧を出す。

**G6. 詳細（上から順に）**。①パンくず（区分 > 大カテゴリー > 中カテゴリー）②ヘッダー：アイコン 118〜128px、名前 22〜28px、サブタイトル（60 字まで。カードと同じ文）、「by 作成者名」（リンク）、バッジ（G8）、**主ボタン**（G7）③情報バー 3〜5 欄：上に値 20px・下にラベル 11px・縦線（App Store／Play の型［高］）で、「区分／更新日／作成者／バージョン／サイズ」を示す。星の欄の代わりに置く ④スクリーンショットの横スクロール ⑤説明 3 行＋「もっと見る」⑥「使うもの・依存するもの」の定型の箇条書き（CWS の Privacy の型［高］）⑦情報欄：左にラベル・右に値で、項目は固定（作成者／公開日／更新日／バージョン／対応環境／サイズ／カテゴリー／連絡先／バージョン履歴）⑧同じ作成者のほかの成果物。幅 ≥ 840px では②③⑦を右 1/3 のパネルに集め、スクロールしても付いてくるようにする（Unity の型［高］）。README を使うなら⑦の後ろに置く。

**G7. 主ボタン**。1 画面に 1 つ、アクセントの 1 色で示す。文言がそのまま状態を表す：「入手」／「¥1,200」／「開く」／「更新」。**「無償」は文字で書く**（有償のものが混ざるので、Play の「無料は書かない」やり方は採らない）。一覧では灰色の面に青い文字、詳細では青い面に白い文字（App Store の型［高〜中］）。カードには「入手済み」のラベルを付ける（Steam の型［中］）。横に逃げ道として「入手できない場合 →」を置く。

**G8. バッジ**。オフィシャルは、チェックと「審査済み」の文言を名前の直下に 1 つ置く（ThemeForest の Quality checked の型［高］）。作成者のバッジは別の軸にする（CWS の Established publisher の型［高］）。インディーズはバッジを付けず、主ボタンの直前に灰色の説明ボックス「審査前です。作成者：○○／確認されていないこと：…」を置く（Steam の型［高］）。警告色は使わない。

**G9. 公開の流れ（作成者の側）**。ボタンは「公開する」の 1 つ。必須の項目は、名前（45 字）／サブタイトル（60 字）／アイコン（512×512 の角の無い正方形。ストアが辺の 20% の角丸を一律にかける。Play の型［高］）／大カテゴリー→中カテゴリー／無償・有償／スクリーンショット（1280×800、5 枚まで。CWS の型［高］）。**インディーズはすぐに掲載し、オフィシャルは「審査待ち」を経て掲載する**。状態は作成者のページに文言で示す。掲載される形はどちらも同じ（L10）。

**G10. マイライブラリ**。入手済みのものを行の形の一覧で示し、「更新あり」の横並びの一覧を添える。空なら「まだ何もありません」＋「ホームへ」の 2 行。

## 3. 持ち込んではいけないもの（理由）

- **星・レビュー・利用数・upvote と、評価の順の並べ替え**。要件で置かないと決まっている。社内の母数では「4.5 ★ (3)」のような中身の無い数字が並ぶ［高］。
- **自動で切り替わるカルーセル、ハンバーガーメニュー、無限スクロール**。それぞれ、読み終える前に次へ流れる／機能を見つけにくくする／フッターにたどり着けない（NN/g）［高／中］。
- **トップページが検索窓だけ**（npm・VS Code Web）。探す言葉を持っていない人が入っていけない［高］。
- **1 段に 20 個並ぶカテゴリーの列**（VS Code・Play）と、**大カテゴリー 14 個**（Fab）。目で追いきれない［高／中］。
- **未審査のものを警告の調子で示すこと**（AMO）と、**作成者を売上で格付けすること**（ThemeForest の Elite Author）。公開する人が減り、「バッジが無い＝新人」に見える［高／中］。
- **審査の有無を詳細ページの一文だけで区別すること**（MS Store）。一覧の段階で分ける［中］。
- **ライセンスの選択・2 種類の購入ボタン・4 つのタブ**（ThemeForest・Fab）。専門家でない利用者が最初に迷う構造そのもの［高］。
- **README をそのまま見せる詳細ページ**（VS Code・HF・npm）。品質が作成者次第になる。項目の決まった欄を先に置く［高］。
- **編集記事の量産**（App Store の Today）。運用が止まると、ストアが放置されているように見える［中］。

## 4. 迷ったときの判定

1. **その画面で押すものは 1 つか**。2 つ以上なら 1 つに減らす（L8）。
2. **専門家でない利用者が 3 回の操作でたどり着けるか**。区分 → カテゴリー → 詳細。4 回目の操作が要るなら、階層か一覧の組み方が間違っている（L1・L5）。
3. **文言だけで、次に何が起きるかが読み取れるか**。アイコンやツールチップに意味を任せていたら、文字に戻す（L8）。
4. **バッジが無いものが劣って見えないか**。同じ行・同じピル・同じ色に戻す（L10・L11）。
5. **更新が止まっても、ストアが放置されたように見えないか**。人が組む横並びの一覧は 1 つまでにし、残りは自動で作る（G2）。
6. **空の画面にも次にできることがあるか**。0 件の画面と、まだ何も入手していない画面を先に設計する（L13）。
7. **その情報をその場所で使うか**。使わないなら情報欄へ移す（L7）。
8. **最後に「App Store の同じ場所ならどう見せるか」と照らし合わせる**。依頼者の言う「しょぼくない」の基準はそこにある。合わないなら、削る方向で直す。
