# 設計ガイドラインと主要なストアの観察（Apple HIG / Material 3 / Fluent 2 / NN/g）

**この内容は Claude の学習データ（記憶）に基づく。実物のページは今回読んでいない。数値は記憶であり、実物と違いうる。**
確信の度合い: ［高］＝公式のガイドラインに明記された数値、［中］＝「こうだったはず」という推測、［低］＝記憶が薄い。ストアの観察は 2024〜25 年ごろの記憶による。

## (a) 画面の骨格（上から順に）

- **App Store (iOS)** ［高］: 下部のタブは 5 つ（Today／ゲーム／App／Arcade／検索）。App タブは、Large Title → 横にスクロールするヒーロー → 横並びの一覧（見出しと「すべて表示」。中身は**行型のカード 3 行で 1 ページとし、横にページ送りする**）の繰り返し。左右のマージンは 20pt［中］。Mac 版は左にサイドバー［中］。
- **Google Play** ［中］: 下部のタブ（ゲーム／アプリ／検索／書籍）と、上部のタブ（おすすめ／ランキング／子ども／カテゴリ／プレミアム）。ランキングは、無料／有料／売上のチップで切り替える。横並びの一覧は、縦型のカードを横にスクロールする形。
- **Microsoft Store (Win11)** ［中］: 左のナビゲーションレール（ホーム／アプリ／ゲーム／ライブラリ）、上部中央に検索ボックス、ヒーローバナー → 横並びの一覧。
- **Steam** ［高］: 上部のナビゲーション → サブナビゲーション（あなたのストア／新着＆注目／カテゴリ）→ 右上に検索。本文は **940px の固定幅**。特集のカルーセル（616×353 と、右に文章）→ セール → カテゴリーのタイル → タブ付きの一覧。
- **M3** ［高］: window size class は compact <600dp／medium 600–839／expanded ≥840。ナビゲーションは、compact では下部の navigation bar（80dp）、medium では rail（幅 80dp）、expanded では drawer（360dp）。マージンは 16dp／24dp、カラムは 4／8／12。**HIG**: ナビゲーションバー 44pt、タブバー 49pt［高］。

## (b) カード 1 枚の構成

- **App Store の行型のカード** ［高］: アイコン 64pt（角丸は辺の約 22.4%≒14pt、連続的な曲線）→ 名前 17pt Semibold 1 行 → サブタイトル 15pt グレー → 右端に「入手」のピル（約 72×28pt、面 #E5E5EA・青い文字の Bold）。有料のものは「¥600」がボタンの文言になる。
- **Play の縦型のカード** ［中］: アイコン（辺の 20% の角丸）→ 名前 14sp 2 行 → 「4.3★」12sp。名前の下に「広告あり・アプリ内購入あり」12sp［高］。
- **Steam のカプセル** ［高／中］: 小 231×87／ヘッダー 460×215／メイン 616×353。割引は、左に「-50%」（面 #4C6B22・文字 #BEEE11）、取り消し線を引いた元の価格、新しい価格を並べる。右にタグのチップを 3〜4 個。
- **M3 Card** ［高］: elevated（1dp）／filled／outlined（1dp outline-variant）。角丸 12dp、内側の余白 16dp、画像は 16:9 か 1:1 で上端に置く。Title Medium 16/24 と Body Medium 14/20、アクションは右下。**Fluent 2**［中］: 角丸 8px、内側の余白 12〜16px、影は shadow4 で、ホバーすると 8。
- **NN/g「Cards」** ［高／中］: カードは**種類の違う情報をまとめる容器**で、同じ種類の項目を比べるならリストのほうが速い。カード全体をクリックできるようにし、並びと画像の比率をそろえる。同じ重さのカードばかりだと、階層が見えなくなる。
- **価格**: Apple と Play では、**ボタンの文言が価格そのもの**（「¥600」→ 押すと「購入」）［高］。無料なら「入手」／「インストール」／Steam は「無料」。**バッジ**: Apple の「Editors' Choice」は名前のすぐ下の小さな文字のラベル、Steam の「早期アクセス」は黄色の地の箱、「Deck 確認済み」は緑のチェック［中］。**バッジは 1 枚に 1 つで、名前のすぐ下か画像の左上に置く**。

## (c) 詳細ページの構成

- **App Store** ［高］: ①アイコン 120pt、名前 22pt Bold、サブタイトル、右下に「入手」のピル ②**メタ情報の行**（評価／年齢／チャート／開発者／サイズ。上に値 20pt、下にラベル 11pt、縦線で区切る）③新機能 ④横にスクロールするスクリーンショット（高さ約 400pt）⑤説明 3 行と「さらに表示」⑥評価 ⑦プライバシー ⑧**情報表**（販売元／サイズ／カテゴリ／互換性／言語／著作権／価格）。
- **Google Play** ［高／中］: ①アイコン、名前、開発者名（緑のリンク）②3 つのセル「4.5★｜100万+｜3歳以上」③**幅いっぱいの緑の「インストール」**（高さ 48dp）④スクリーンショット ⑤「このアプリについて →」⑥データセーフティ ⑦評価 ⑧類似アプリ。
- **Microsoft Store** ［中］: 左に大きなアイコン・名前・発行元・「入手」（#0078D4、角丸 4px、高さ 32px）、右にスクリーンショット。下に説明 → 「追加情報」の表。
- **Steam** ［高］: ①パンくずリストとタイトル 26px ②左に動画／スクリーンショット 600×337、右にヘッダー 460×215、短い説明、レビューの概要、リリース日、開発元、タグのチップ ③**購入の箱**（濃い色の面に「Xを購入」、価格、緑のボタン）④このゲームについて ⑤システム要件（最低／推奨の 2 列）。

## (f) 余白・角丸・グリッド・影

- **HIG** ［高］: タッチ領域の目標 **44×44pt**、リストの行 ≥44pt、区切り線の inset 16pt、マージン 16／20pt、セルの角丸 10pt。
- **M3** ［高］: **4dp グリッド**、8dp 刻み、タッチ領域の目標 **48dp**（隣との間隔 8dp）。shape 0／4／8／12／16／28／full。elevation 0／1／3／6／8／12dp。リストの行 56／72／88dp。チップ 32dp・角丸 8dp。ボタン 40dp・full。検索バー 56dp。トップバー 64dp。
- **Fluent 2** ［高／中］: 4px グリッド、角丸 2／4／6／8／circular（Win11 はウィンドウ・カードが 8px、コントロールが 4px）、影 2／4／8／16／28／64。
- **Steam** ［中］: 本文の幅 940px、パディング 16px、角丸 0〜3px、影は無い。

## (g) 信頼の印と、印の無いものの見せ方

- Apple は「審査済み」を**表示しない**（すべてが審査済みであることが前提）。信頼は、Editors' Choice のラベル、プライバシーの表、販売元の名前と開発者のページで示す［高／中］。Play は「エディターのおすすめ」と、政府機関のアプリに付く青いバナー［中］。MS Store は「提供元」の名前だけ［低］。
- Steam の「早期アクセス」は、**格下げではなく、状態を説明する箱**（何が未完成かを開発者の言葉で書く）。「Deck 確認済み」は、チェックと短い理由のリスト［中］。
- ここから言えること: 未審査のものを警告色で見せない。「審査済み」は 1 つの明確な印（チェックと文言）で示し、未審査のものは印が無いだけにして、説明の箱で「誰が作り、何が未確認か」を示す。

## (h) 探す動線

- 検索: Apple は専用のタブ（入力が空のときはトレンドの語を出す）、Play は常に表示される検索バー、Steam は右上の小さな検索欄と、検索ページの左の絞り込みの列［高／中］。カテゴリー: Apple は横並びの一覧のセル、Play はタブ → チップ → 一覧、Steam は大きなジャンル → 横並びの一覧とタグのチップ［中］。
- **NN/g** ［高／中］: 一覧に最低限要るのは「画像＋名前＋価格＋ほかと区別できる属性 1 つ」。見た目で選ぶ商品はグリッド、仕様を比べる商品はリストにする。件数を表示する。選択済みのフィルターは、一覧の上に**外せるチップ**で示す（M3 の filter chip: 選ぶとチェックが付き、色の面になる）。無限スクロールより「もっと見る」ボタンがよい。**カテゴリーのページはリストだけにしない**——上に中カテゴリーの画像のタイル、短い説明、少数の特集、その下に一覧。ハンバーガーメニューは見つけやすさを下げる（常に見えるタブを使い、5 つまでにする）［中］。自動で送るカルーセルは嫌われる［高］。

## (i) 専門家でない利用者が迷わない工夫

- ボタンは**動詞 1 語**で、状態が進むと文言も変わる（入手 → 開く、¥600 → 購入）。価格をボタンに入れると、「いくらで何が起きるか」が 1 か所で分かる［高］。
- 最初の 1 画面に、主役は 1 つ。視覚的な階層（大きさ・色・位置・余白）で、検索 → いま勧める 3 つ → 大カテゴリーの順に見せる［中］。横並びの一覧は、「3 行×1 ページ」が見比べなくても拾える単位［中］。
- 空の状態では、「なぜ空か＋次の一手」を 1 文で示す［中］。情報表は**左にラベル、右に値の 2 列**にし、項目名を固定する［高］。

## (j) 取り入れる点と、取り入れない点

**取り入れる**: ①App Store の行型のカードと、3 行ずつ横にページ送りする横並びの一覧［高］ ②Play の、3 つのセルが並ぶメタ情報の行（値が上・ラベルが下・縦線で区切る）の中身を「審査済み／更新日／作成者」に差し替える［中］ ③Steam の購入の箱と 2 色のバッジで、無償／有償を一目で分かるようにする［中］ ④Steam の早期アクセスの箱を「未審査」の説明の箱に使い、タグのチップは作成者が付ける［中］ ⑤M3 の数値（4dp／48dp／12dp／type scale）を土台にし、Fluent の 8px の角丸で Windows とそろえる［高］ ⑥NN/g の、カード全体をクリックできること・件数の表示・「もっと見る」・フィルターのチップ・中カテゴリーのタイル［高／中］ ⑦作成者のページ（名前 → その人の作品の一覧）［高］。

**取り入れない**: ①星・レビューと、評価の順の並べ替え ②自動で送るカルーセル、ハンバーガーメニュー、無限スクロール ③Steam の情報の密度と 13px の本文、割引や期限の演出 ④Today 型の編集記事を大量に作ること（更新が止まると、ストアが放置されているように見える） ⑤未審査のものを色や位置で格下げすること（公開する人が減る）。
