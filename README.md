# 成果物のストア（試作）

組織の中で作られたツールや素材（「成果物」）を、App Store や Google Play のように探して入手でき、自分でも公開できるストアの試作です。

- **区分は 2 つです**。オフィシャル（審査済み）と、インディーズ（審査なし。だれでもすぐに公開できる）があります
- **大カテゴリー → カテゴリー**の順にたどって探します（ツール → 表計算、素材 → デザイン仕様書 など）
- **星やレビューはありません**。代わりに「ストアによる確認」（ストアが何を確かめたか）と「作成者からの情報」を分けて表示します
- **基本は無償です**。有償の成果物は、部署間の費用の付け替えで利用します（利用者は費用を計上する部署のコードを選ぶだけで、経理の処理は裏側で自動的に行う設計です）

**これは試作です**。画面はブラウザで開くだけで動きますが、公開・審査・入手・申し込みの操作の結果は、そのブラウザの中にだけ残ります。掲載している成果物・人物・部署・部署コードは、すべて架空のものです。

## すぐに見るには

1. このページの緑の「Code」ボタン →「Download ZIP」で、すべてのファイルをまとめてダウンロードします
   （直接のリンク: https://github.com/feseisen/commons-store/archive/refs/heads/main.zip ）
2. ZIP を展開し、`store.html` をブラウザ（Edge や Chrome）で開きます

インストールは不要です。インターネットに接続できない環境では、フォントだけが OS の日本語フォントに替わります。

### 試作でできること

- オフィシャル／インディーズの切り替え、大カテゴリー → カテゴリー → 詳細への移動、区分をまたいだ検索
- 無償／有償の表示。有償の成果物で金額のボタン（例:「¥3,000」）を押すと、費用の計上部署を選んで申し込めます
- 「公開する」のフォーム（入力を終えるとインディーズに公開されます。「審査を申請」をオンにしておくと、審査待ちに並びます）
- 審査担当者の「承認する／差し戻す」（左下の名前から、審査担当者の役割に切り替えられます）
- 参考にした成果物（どの成果物をもとに作ったか）の表示。「公開した成果物」では、自分の成果物の審査の状況と、参考にされた件数を確認できます
- OS の設定に合わせたライトモードとダークモード、PC とスマートフォンそれぞれの画面幅への対応

### 試作でできないこと

- 入手（ダウンロード）と申し込みは、通知を表示するだけです
- ログイン機能がないので、利用者は架空の 1 人（画面の名前は「佐藤（架空）」）に固定されています
- 操作の結果はそのブラウザの `localStorage` にだけ残り、ほかの人には見えません

これを、組織で共有する本番のデータと権限に置き換えるための設計と手順は、`docs/backend/` にあります。

## データを修正して画面を作り直す

`catalog.json` や `categories.json` を修正したら、このフォルダで次のコマンドを実行します（Python 3 の標準ライブラリだけで動きます。3.11 で動作を確認しました）。

```
python build_store.py
```

SharePoint に取り込む CSV を作り直すときは、次のコマンドを実行します。出力先は `docs/backend/import/` です。

```
python tools/export_for_sharepoint.py
```

Windows で `python` が見つからないときは、`py` に置き換えてください。

## 本番で運用するには

まず `docs/backend/README.md` を読みます。急ぐときは、`docs/backend/architecture.md` の 1 章（結論）と、`docs/backend/implementation-guide.md` の「導入先で確かめること」を先に読みます。

- 本線は、サーバーもバージョン管理の基盤も持たない組織を前提に、Microsoft 365 の標準の機能だけで作ります
- 書き込みの操作はすべて「受付のリストに 1 行書く → フローが確かめて反映する」という形にそろえてあるので、画面を Power Apps から SPFx に替えても、フローとデータはそのまま使えます
- 有償の利用では、提供部署が承認すると付け替えの記録が作られ、月末に締めて、翌月度に計上するために経理システムへ渡します。経理システムへ渡すファイルの形式と、経理システムの側で必要になることは、`docs/backend/data-model.md` の 13 章にあります
